# Static rebuild of the Cervejarte blog (cervejarte.org/blog)

This repo is the GitHub Pages site for the domain `cervejarte.org`:

```
./
├── CNAME          cervejarte.org
├── .nojekyll
├── index.html     placeholder that redirects to /blog/ — replace with the recovered main site
├── 404.html       the blog's "page not found" (GitHub Pages only uses the root 404)
├── blog/          the blog, at its original address http://cervejarte.org/blog/...
└── tools/         the scripts that build blog/ (this folder)
```

Old links such as `cervejarte.org/blog/2007/02/12/belgian-wit/` keep working.

`tools/` is published along with the site (e.g. `cervejarte.org/tools/build_site.py`).
It only holds code and styles — no data from the WordPress backup.

## Previewing locally

From the repo root:

```bash
python3 tools/serve.py
```

Then open http://localhost:8000/blog/. This server tells the browser not to cache,
so you always see the latest build (plain `python3 -m http.server` lets Safari
keep showing old copies of pages you visited before).

## Rebuilding the blog

You need the two backup files, which are **not** in this repo: the SQL dump
(`cervejar_wrd2.sql`) and `wp-content-blogcervejarte-24set2019.tar.gz`. No PHP or
database is used. From the repo root, with the backups one folder up:

```bash
mkdir -p /tmp/wp-extract && tar -xzf ../wp-content-blogcervejarte-24set2019.tar.gz -C /tmp/wp-extract wp-content/uploads
```

```bash
python3 -I tools/parse_sql.py ../cervejar_wrd2.sql /tmp/wp-data.json
```

```bash
python3 -I tools/build_site.py /tmp/wp-data.json /tmp/wp-extract/wp-content/uploads .
```

A rebuild replaces only `blog/`. It leaves the rest of the repo alone (including
`tools/`), and it only rewrites `index.html` / `404.html` at the root if they are
still the generated placeholders (they carry a `generated by build_site.py`
marker). So you can drop the recovered main site into the repo root without it
being overwritten.

- `parse_sql.py` reads the dump as text and drops commenter e-mail, IP and
  user-agent columns (and user logins/passwords/e-mails) before anything is written.
  Keep `/tmp/wp-data.json` out of the repo: it still holds comments and drafts.
- `build_site.py` keeps the `/%year%/%monthnum%/%day%/%postname%/` permalinks,
  page paths, `/category/...` archives (and `/tag/...`, though the blog has no tags),
  date archives, attachment pages, approved comments (threaded, closed) and an RSS
  `feed.xml`. E-mail addresses typed inside comment text are replaced with
  “[e-mail removido]”. Only media files are copied from `wp-content/uploads`.
- Calculator forms whose JavaScript was stripped by a later WordPress edit are
  restored from the most recent revision that still had it (the decoction
  calculator, from 2011).
- The menu: pages with child pages get a dropdown. Calculators that live inside
  posts are added to the Calcularte dropdown via `MENU_EXTRAS` at the top of
  `build_site.py`.
- The look lives in `tools/style.css` and `tools/menu.js` (copied to
  `blog/assets/`, linked with a `?v=` content hash so browsers pick up changes).
  The original 2011 header image is copied to `blog/assets/cabecalho.png`.
- New posts (written after the WordPress era) live in `tools/posts/`, one `.txt`
  file each: header lines (`title:`, `date: YYYY-MM-DD HH:MM`, `slug:`,
  `categories:` with existing category names), a line with `---`, then the text.
  Blank lines separate paragraphs; simple HTML is allowed. Rebuild to publish.
- `SITE_HOST` and `BASE` at the top of `build_site.py` set the domain and the path.
